# 프로젝트 딥다이브 준비법

면접에서 프로젝트는 기능 목록보다 **기술 선택의 이유**가 중요합니다.

프로젝트마다 아래 질문에 답을 준비합니다.

## 1. 문제

- 어떤 서비스를 만들었는가?
- 서버가 반드시 해결해야 했던 문제는 무엇인가?

## 2. 구조

- Client
- Gateway/API
- Game Server
- DB
- Cache
- Queue

데이터가 이동하는 순서를 그릴 수 있어야 합니다.

## 3. 가장 중요한 기술 선택 3개

예:
- TCP를 선택한 이유
- Room 단위 Job Queue를 선택한 이유
- Redis를 어디에 쓰고 어디에는 쓰지 않았는지

## 4. 장애 시나리오

- 클라이언트 연결 종료
- 중복 패킷
- 서버 재시작
- DB timeout
- 캐시 장애
- 게임 종료 결과 저장 실패

## 5. 성능

- 예상 동접
- Tick
- 패킷 빈도
- DB 호출 빈도
- 락 경합 지점
- 병목 측정 방법

## 6. 개선점

"완벽하게 구현했습니다"보다 다음 답변이 좋습니다.

> 현재 구조에서는 X가 병목이 될 수 있습니다. 다음 단계에서는 Y를 측정한 뒤 Z 구조를 검토하겠습니다.
